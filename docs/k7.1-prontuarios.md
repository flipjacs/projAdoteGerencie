Não há escrita nem consulta pública.

## Modelo e migration

V10, posterior a V9, cria:

- `prontuario`: animal, ONG, autor autenticado, tipo, campos clínicos, datas e `@Version`.
- `correcao_prontuario`: responsável autenticado, justificativa, instante, snapshots completos antes/depois e versões anterior/posterior.

A chave composta `(animal_id, ong_id)` referencia `(animal.id, animal.ong_id)`, impedindo inconsistência física entre animal e ONG. FKs protegem autor, corretor e registro; índices suportam animal/data/tipo e histórico cronológico. Correções são únicas por registro/versão posterior. Snapshots usam MEDIUMTEXT para acomodar JSON escapado de campos válidos, sem limitar indevidamente a capacidade clínica. Não há cascade de exclusão nem endpoint de exclusão.

Os oito tipos reais são `CONSULTA`, `VACINA`, `VERMIFUGACAO`, `EXAME`, `CIRURGIA`, `MEDICACAO`, `TRATAMENTO`, `OBSERVACAO`. Os seis exigidos estão contemplados; os dois últimos também existem no enum e no formulário Laravel/React. Todos compartilham o mesmo conjunto de campos, como na referência; nenhuma tabela por tipo ou integração adicional foi criada.

## Contrato para K7.2

Todas as rotas exigem JWT. JSON plano, sem envelope em detalhes. Páginas: `{content, number, size, totalElements, totalPages}`, `page=0`, `size=15` por padrão, limite 100. Página negativa, tamanho inválido e offset acima do limite JPA recebem 400.

| Método | Endpoint | Acesso |
|---|---|---|
| POST | `/api/ong/animais/{animalId}/prontuarios` | Administrador/veterinário da ONG; 201 |
| GET | `/api/ong/animais/{animalId}/prontuarios` | Administrador/veterinário/voluntário; 200 |
| GET | `/api/ong/animais/{animalId}/prontuarios/{id}` | Mesmos leitores; 200 |
| PATCH | `/api/ong/animais/{animalId}/prontuarios/{id}/corrigir` | Administrador/veterinário; 200 |
| GET | `/api/ong/animais/{animalId}/prontuarios/{id}/correcoes` | Mesmos leitores; 200 |
| GET | `/api/me/animais-adotados/{animalId}/prontuarios` | Adotante titular após entrega; 200 |
| GET | `/api/me/animais-adotados/{animalId}/prontuarios/{id}` | Mesmo adotante, somente leitura; 200 |

Listas clínicas institucionais e pessoais aceitam `tipo`, `de`, `ate` (datas inclusivas `YYYY-MM-DD`, `ate >= de`). Ordem: data do procedimento descendente, id descendente. Correções: criação e id ascendentes, com a mesma paginação. Recursos de outra ONG, outro animal ou sem adoção autorizada recebem 404.

### Criar

```json
{
  "tipo": "CONSULTA",
  "titulo": "Avaliação clínica",
  "descricao": "Informações clínicas",
  "dataProcedimento": "2026-11-24",
  "profissionalResponsavel": "Dra. Ana",
  "medicamentos": null,
  "observacoes": null
}
```

Obrigatórios: tipo válido, título não vazio até 120 caracteres, descrição não vazia até 10.000, data válida não futura. Opcionais/nulos: profissional até 120, medicamentos e observações até 5.000 cada. Limites contam caracteres Unicode, não bytes/unidades UTF-16. A data respeita também o intervalo MySQL 1000–9999. Texto é aparado; opcionais vazios viram null. Valores textuais devem ser strings. Campos desconhecidos/internos, inclusive ONG, animal, autor e versão na criação, são recusados com 400. ONG/animal vêm da autorização e da rota; autor vem da sessão. `profissionalResponsavel` é a descrição livre que já existe no Laravel, não a identidade de autenticação.

### Resposta institucional

```json
{
  "id": 1,
  "animal": {"id": 1, "nome": "Animal"},
  "tipo": "CONSULTA",
  "titulo": "Avaliação clínica",
  "descricao": "Informações clínicas",
  "dataProcedimento": "2026-11-24",
  "profissionalResponsavel": "Dra. Ana",
  "medicamentos": null,
  "observacoes": null,
  "registradoPor": {"id": 2, "nome": "Responsável original"},
  "criadoEm": "2026-11-24T15:00:00Z",
  "atualizadoEm": "2026-11-24T15:00:00Z",
  "versao": 0
}
```

Datas acima são apenas exemplos de formato de contrato. Resposta do adotante contém somente `id`, `animal` e os sete campos clínicos; nenhuma informação administrativa é acrescentada.

### Corrigir

```json
{
  "titulo": "Título corrigido",
  "observacoes": null,
  "justificativa": "Correção da informação registrada",
  "versao": 0
}
```

PATCH parcial: campos omitidos permanecem; null explícito apaga somente opcionais. Obrigatórios clínicos não aceitam null. Justificativa não vazia até 2.000 caracteres e versão inteira não negativa são obrigatórias. Deve haver ao menos uma mudança clínica efetiva; no-op recebe 400. Versão obsoleta recebe 409, sem alterar dados ou criar histórico. Não reenviar automaticamente; consultar o detalhe atual e permitir revisão do formulário. Autor original é preservado.

Correção bloqueia o registro após validar a ONG e o animal, atualiza com `@Version` e grava ambos os snapshots na mesma transação. Falha no histórico desfaz também os dados e a versão. Históricos incluem `id`, `criadoEm`, `justificativa`, `corrigidoPor:{id,nome}`, `dadosAnteriores`, `dadosNovos`, `versaoAnterior`, `versaoPosterior`; os snapshots contêm os sete campos clínicos.

### Erros

`application/problem+json`: `status`, `detail`, `code`. Sem conteúdo clínico nos detalhes de erro.

- 400 `PRONTUARIO_DADOS_INVALIDOS`: corpo, tipo, campo, tamanho, data, versão ou filtro inválido.
- 401: JWT ausente/inválido/expirado, segundo Spring Security existente.
- 403: perfil/operação sem autorização; conta, vínculo ou ONG não habilitados seguem o mecanismo de sessão existente (`ACESSO_NEGADO` ou `PRONTUARIO_ACESSO_NEGADO`).
- 404 `PRONTUARIO_NAO_ENCONTRADO`: animal/registro inexistente ou não autorizado para o contexto.
- 409 `PRONTUARIO_CONFLITO`: estado ADOTADO/FALECIDO na criação, versão desatualizada, conflito de persistência/lock.

Rotas de escrita pessoal, histórico administrativo pessoal, edição comum ou exclusão são negadas pelo Security (403 quando autenticado). ADMIN_PLATAFORMA não recebe acesso operacional.

## Diferenças deliberadas

- Prefixo `/api` e paginação zero mantêm as convenções Kotlin; Laravel usa `/api/v1` e páginas iniciadas em um.
- `criadoEm`/`atualizadoEm` seguem os demais módulos Kotlin, em lugar de `createdAt`/`updatedAt`.
- Versão obrigatória no PATCH reaproveita `@Version`: a checagem de atualização que o React fazia no cliente passa a ser aplicada atomicamente pelo servidor Kotlin.
- Snapshots JSON serializados em MEDIUMTEXT, em vez do tipo JSON nativo Laravel, simplificam a persistência com o Jackson existente e preservam a estrutura dos dados.
- Datas anteriores ao intervalo suportado por MySQL recebem 400 em vez de depender de erro do banco.
