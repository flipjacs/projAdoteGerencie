## Adaptações recomendadas sem redesign

Preservar paleta, hierarquia, margens16px, espaços internos20px, títulos32px, cards de borda fina e botões pill. Usar o mesmo fluxo de texto e organização do valor/frequência no card pessoal. Para listas institucionais, reproduzir o formato móvel de rótulo/valor em vez de tentar encaixar tabela horizontal. Formulários devem rolar verticalmente, com notas e ação principal após os campos, como no React. Preservar controles nativos Android para seleção/data/teclado decimal e documentar a diferença de renderização, sem adicionar etapas inexistentes no Web.

Manter confirmação de encerramento pessoal junto ao contexto; publicação e despublicação com explicação explícita e opção Voltar. Não atribuir ao React uma confirmação modal de parcela que ele não possui. Para o público, exibir somente a projeção reduzida: ONG, título, período, data de publicação, totais e categorias. Identidade de padrinho/operadores e detalhes de parcelas pertencem às telas privadas.

## Limites e verificação visual

Foram inspecionadas visualmente as PNGs de formulário, lista pessoal, contexto do animal, parcela institucional, publicação e demonstrativo público. As imagens adicionais documentam rolagem de interfaces reais. Não foi alterado DOM para compor as telas. A captura usa CSS responsivo, sem emular teclado/AVD ou barra de status Android. Ausência de fotografia é estado real de fallback. Sessões e resultados de rede são sintéticos e não testam cookies reais, autorização do servidor, privacidade efetiva da API, transações ou persistência. O snapshot público sintético contém apenas os campos visuais do demonstrativo, sem informação pessoal.

As screenshots servem de referência para comparação com screenshots Android reais; esta tarefa isolada não comprova a fidelidade final nem conclui K8.2.
